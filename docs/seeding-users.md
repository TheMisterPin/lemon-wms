# Seeding Users

Creates one user per role so you can log in to both sides of the app immediately after setup.

## Prerequisites

1. PostgreSQL running locally on port 5432 with a database named `wms_db`
2. `.env.local` at the repo root with at minimum:
   ```
   DATABASE_URL="postgresql://localhost:5432/wms_db"
   ```
3. Migrations applied:
   ```
   npx prisma migrate dev
   ```
4. Prisma client generated:
   ```
   npx prisma generate
   ```

## Run the seed

```
pnpm seed:users
```

The script is idempotent — running it multiple times will not create duplicate users.

## Seeded accounts

### Office side — `/login`

| Role | Email | Password |
|---|---|---|
| Owner | `owner@lemon-wms.local` | `owner1234` |
| Office Manager | `office.manager@lemon-wms.local` | `manager1234` |
| Office Worker | `office.worker@lemon-wms.local` | `worker1234` |

### Floor side — `/floor`

| Role | Badge number | PIN |
|---|---|---|
| Warehouse Manager | `USR-0004` | `1111` |
| Warehouse Worker | `USR-0005` | `2222` |

Floor login requires a registered device. If no device exists yet, register one via the setup wizard first, then use the badge number and PIN above.

## What the script does

- Hashes all passwords and PINs with bcrypt (cost factor 10) — plain-text credentials are never stored
- Uses `upsert` on `badgeNumber` so re-runs are safe
- Creates a `SerialNumberConfig` entry for the `USER` entity type with `lastValue = 5`, so the next badge number generated by the app starts at `USR-0006` and does not collide with the seeded users
